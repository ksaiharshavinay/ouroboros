Confidence-Calibrated Lineage for Policy-Constrained Root Cause Analysis in Enterprise Data Reliability Systems
Sai Harsha Vinay Kudikala Independent Research Proposal
Abstract—Enterprise data incidents are difficult to diagnose because end-to-end lineage is often incomplete, metadata quality is uneven, and remediation actions must satisfy governance and compliance constraints. Prior work has explored LLM-assisted root cause analysis, missing-lineage inference, and policy-aware remediation, but these are mostly addressed separately rather than as one enterprise data reliability framework. This paper proposes Confidence-Calibrated Lineage RCA (CCL-RCA), a framework that assigns confidence scores to observed or inferred lineage links, propagates those scores through a causal graph, ranks root-cause hypotheses for data-quality incidents, and recommends remediation actions filtered by governance policy constraints. The expected contribution is a safer and more practical path toward semi-autonomous data reliability systems in enterprise environments.
Index Terms—data reliability, data lineage, root cause analysis, policy-aware remediation, data observability, metadata trust, enterprise governance.
I. INTRODUCTION
Modern enterprises depend on pipelines, warehouses, catalogs, and dashboards for operational and strategic decisions. When a data incident occurs, engineers typically rely on observability signals, lineage, and metadata to trace the origin of failure. However, three problems remain persistent: lineage is often incomplete or inferred rather than directly observed; metadata systems are useful for discovery but not always trustworthy enough for operational decision-making; and remediation actions must satisfy compliance, ownership, and governance constraints rather than technical feasibility alone.
These limitations motivate a new framework for enterprise data reliability in which lineage is treated as confidence-weighted evidence instead of binary truth, and remediation is filtered through policy-aware constraints. This framing supports a more realistic and explainable path toward semi-autonomous incident response.
II. PROBLEM STATEMENT
Existing RCA approaches can help summarize incidents, but many assume that dependency structure is sufficiently known and trustworthy. In enterprise data environments, that assumption is weak because lineage can be missing, stale, or inferred; metadata can be incomplete or low-trust; and an apparently effective remediation can still violate governance or ownership rules if applied automatically.
The central research question is: How can enterprise data incidents be diagnosed and remediated when lineage and metadata are uncertain, while remediation must remain policy-compliant and explainable?
III. RESEARCH GAP
The specific gap addressed by this work is the lack of a framework that uses incomplete or inferred lineage with explicit confidence scores, then uses those scores to rank RCA hypotheses and choose remediation actions under enterprise data-governance constraints. Prior work addresses lineage inference, LLM-assisted RCA, or policy-aware remediation separately, but not as a unified enterprise data reliability framework.
This creates a practical blind spot. If lineage is uncertain, RCA may over-trust weak dependencies. If policy context is missing, remediation recommendations may be operationally useful but organizationally unsafe. A confidence-calibrated and policy-constrained approach directly targets this unsolved intersection.
IV. PROPOSED METHODOLOGY
A. Incident Signal Collection
The system ingests data-quality and observability events such as freshness violations, null spikes, schema drift, failed jobs, delayed ingestion, and downstream dashboard anomalies.
B. Confidence-Calibrated Lineage Graph
A lineage graph is built across sources, pipelines, tables, columns, and dashboards. Each edge receives a confidence score based on provenance, such as direct runtime lineage, SQL-parsed lineage, inferred lineage, steward-confirmed lineage, or stale and conflicting lineage.
C. Metadata Trust Scoring
Metadata trust is modeled explicitly using signals such as owner availability, documentation freshness, glossary mapping presence, PII label verification, SLA availability, and last validation time. This allows the framework to distinguish between richly governed assets and poorly documented ones.
D. RCA Hypothesis Ranking
Candidate root causes are ranked using path confidence, telemetry match, metadata trust, incident history, and business impact. The goal is not only to find a plausible upstream cause, but to rank the most defensible explanation under uncertainty.
Score(c) = αP₍c₎ + βT₍c₎ + γH₍c₎ + δM₍c₎ + εB₍c₎
where P is lineage path confidence, T is telemetry alignment, H is historical support, M is metadata trust, and B is business impact.
E. Policy-Constrained Remediation Recommendation
Potential remediation actions such as rerunning jobs, backfilling partitions, quarantining datasets, or blocking downstream publication are generated and filtered using policy rules. Examples include requiring approval before republishing sensitive datasets, prohibiting auto-backfill for regulated assets, and escalating incidents affecting tier-1 executive dashboards.
This makes the framework semi-autonomous rather than fully autonomous, which is more realistic for enterprise deployment and easier to evaluate safely.
V. EVALUATION PLAN
The framework will be evaluated against three baselines: binary-lineage RCA, confidence-aware RCA without policy filtering, and the full CCL-RCA method with policy-aware remediation. Experiments will use synthetic and enterprise-inspired scenarios involving schema drift, missing partitions, duplicate loads, delayed ingestion, broken joins, incomplete lineage, and low-trust metadata.
Evaluation metrics will include Precision@1, Precision@3, mean reciprocal rank, unsafe recommendation rate, policy violation rate, human acceptance rate, and reduction in mean-time-to-diagnosis. Together, these metrics assess RCA quality, remediation safety, and operational usefulness.
VI. EXPECTED CONTRIBUTIONS
This work is expected to contribute four outcomes: a confidence-calibrated lineage model for enterprise data incident analysis; a joint RCA and remediation framework combining telemetry, lineage uncertainty, metadata trust, and governance rules; a policy-constrained recommendation layer specialized for data reliability systems; and an evaluation design for fault scenarios involving partial lineage and metadata uncertainty.
VII. CONCLUSION
This proposal argues that enterprise data reliability systems should not assume lineage is fully correct, metadata is fully trustworthy, or remediation is always safe. By modeling lineage as uncertain evidence and combining it with metadata trust and policy-aware filtering, the proposed framework aims to improve RCA quality while reducing unsafe remediation decisions.
